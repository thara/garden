## Goal

エージェントの実行を観測・中断・再開できる小さな Harness を作り、ツール実行をどこで、どんな根拠で許可するかを、動くコードと実行記録で比較できるようになる。

## Roadmap

### 1. エージェントを動かす

- [ ] OpenAI互換APIを一つつなぎ、モデルが read_file と write_file を呼べるようにする。実験では決め打ちのツール呼び出しも流せるようにする。
- [ ] 成果物: 単一プロセスの Harness
    - モデルの応答、ツール要求、実行結果を順に追える。決め打ちの入力で同じ経路を繰り返し検証できる。

### 2. 実行を止めて再開する

- [ ] ツール実行の前後でプロセスを強制終了する。特に、書き込みは成功したが、その結果を記録する前に落ちた場合を試す。
- [ ] 成果物: 再開できる run
    - どこから再開されるか、同じ書き込みが再実行されるか、実行済みか判断できない状態をどう扱うかが分かる。

### 3. ツール実行を制御する

- [ ] `notes/` の読み取りと `out/` への書き込みを許可する。許可外のパスやシンボリックリンク経由の書き込みを与え、認可判断と実際の書き込み先を確かめる。
- [ ] 成果物: 認可を通るツール実行経路
    - どの run が、どの操作を、どの対象に要求し、なぜ許可・拒否されたかが残る。

### 4. 判断を実行から切り離す

- [ ] 書き込みを承認待ちにし、承認前にプロセスを落とす。再開後に、承認済みの操作と、パスや内容が変わった操作をそれぞれ試す。
- [ ] 成果物: 承認後に再開できる run
    - 承認を具体的な操作に結びつけ、別の操作への流用を拒否できる。

### 5. 指示から実行時の制約を作る

- [ ] 固定ポリシーと、依頼文から別のエージェントが作った制約を比較する。「要約を保存して」のように保存先が曖昧な依頼も与える。
- [ ] 成果物: 同じツール要求に対する判断の比較表。
    - 必要な操作を止めた例と、余計な操作を許した例が分かる。 [Sapien](https://arxiv.org/abs/2610.00797) で気になっていたアイデアはここで試せる。

### 6. 権限を委譲する

- [ ] 親の run から子の run に、特定のファイルを読む権限だけ渡す。別ファイルへのアクセス、期限切れ、別の run での使い回しを試す。
- [ ] 成果物: 委譲から実行まで追える記録。
    - 固定ポリシーによる認可と、実行時に渡した権限による認可の違いを比較できる。
    - [RuntimeTickets](https://arxiv.org/abs/2611.03772) を検証
