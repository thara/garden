# Agent-native Computing Manifesto

## Vision

Agentによる自律的な計算を、信頼できるコンピューティングの基本的な構成要素として扱えるようにする。

人間は目的と制約を与え、Agentはその範囲で実現方法を探索する。目的や実現方法は、実行を通じて具体化・変更されることもある。

プラットフォームは、そうした自律性を許容しながら、権限や外部への副作用を制御し、実行を観測可能にする。

人間は、何が保証され、実行がどのような結果をもたらしたかを確かめ、必要に応じて介入できる。

## 設計原則

### 仕様をfirst classの成果物にする

目的、制約、保証すべき性質を、可能な範囲で明示する。

仕様は実装を理解・検証・交換するための基準となる。機能、副作用、性能、実行環境など、必要な契約が維持される範囲で、実装を交換可能にする。

仕様は最初から完全である必要はなく、探索や実行を通じて具体化・更新されてもよい。ただし、未確定の性質を保証済みとして扱わない。

### 検証可能な境界の内側で自律性を認める

Agentに実現方法の選択を委ねる。

権限、外部への副作用、リソース消費など、実行の安全性に関わる境界は、事前に検査できるか、実行時に強制できる形で定める。

自律性を認めることと、無制限の権限を与えることは異なる。

### 保証をAgentの知能から独立させる

Agentが誤った計画を立てたり、予期しない振る舞いをしたりしても、維持すべき性質を定義する。

保証の根拠を、Agentの判断能力ではなく、仕様、検証、実行時の制約、外部システムとの契約に置く。

保証の適用条件と限界、未検証の範囲を明示する。

### 自律的な実行を追跡可能にする

仕様、実装のRevision、検証結果、認可や承認の記録、状態変化、外部への副作用を関連付ける。

実行の経緯と結果を追跡し、何が起きたか、何が保証されていたか、何が未確定なのかを確認できるようにする。

ソースコードを参照できる場合は、実行を理解するための証跡の一部として扱う。

### 実装の由来ではなく、保証と権限に基づいて信頼する

人間による実装もAgentによる生成物も、要求される契約と保証に照らして評価する。

生成元や検証者の情報は、保証を裏付ける証跡の信頼性を判断する材料となるが、実装の由来だけで特別な実行上の地位を与えない。

実装が要求される性質を満たしていることと、個々の実行が現在のポリシーに基づいて許可されることは、区別して判断する。
