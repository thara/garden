## Research

- AgentCap — Capability-Based Runtime Authorization for Secure LLM Agent Execution
	- [[2611.00729] AgentCap: Capability-Based Runtime Authorization for Secure LLM Agent Execution](https://arxiv.org/abs/2611.00729)
	- 問題: 従来のアクセス制御では「このAgentはこのToolを使えるか」を判定するが、それだけでは攻撃者が外部ドキュメントを通じてAgentに不正な送金先を指定させた場合などに対処できない。
	- アプローチ: Agentが提案した操作と、その操作を許可する根拠を分離する
		- Request-scoped Capability：Ed25519署名付きJWTを短命・予算付きで発行し、ツール実行直前に検証する。
		- Argument Provenance：送金先などの重要な引数が、信頼されたTask Contextに由来するかを検証する。
	    - Delegation Attenuation：子Agentへの委譲では、予算・有効期限・再委譲深度を拡大できない。
	    - Policy Surface Analysis：権限の危険な組み合わせと、矛盾によって実行不能になるワークフローをデプロイ前に検出する。
	- 制約・未解決課題
		- ポリシーの正しさは保証されない
			- 重要な引数をProvenance検証の対象から漏らせば、不正操作を許す可能性がある
		- Agentが申告するIntentは信頼できない
			- Intentの許可リストは操作の制約にはなるが、ユーザーの本当の意図を証明するものではない
		- 実験は各モデル・Benchmark条件につき1回で、分散や信頼区間は示されていない
